# 後台部署步驟（Google Apps Script）

新後台把身分驗證和權限判斷都放在 Apps Script 裡，前端只負責顯示。照下面順序做，大約 15 分鐘。

## 1. 建立新的 Google Sheet 與後台

1. 用 Tori 的 Google 帳號開一份**新的** Google Sheet，命名例如「頭沐任務系統」。
2. 選單「擴充功能 → Apps Script」，把編輯器裡預設的程式碼全部刪掉，貼上 `Code.gs` 的內容，存檔。
3. 上方函式選單選 `setup`，按「執行」。第一次會要求授權，照畫面允許。
4. 執行完打開「執行記錄」，會看到 `管理者初始 PIN：xxxxxxxx`。先記下來，登入後馬上改掉。

`setup` 會建立 Members、Tasks、Comments 三個工作表和管理者帳號。PIN 只存雜湊值，連 Sheet 裡也看不到明碼。

## 2. 部署成網頁應用程式

1. 右上「部署 → 新增部署作業」，類型選「網頁應用程式」。
2. 「執行身分」選**我**，「誰可以存取」選**任何人**。
   - 「任何人」只代表網址連得到。每個動作都要先用 PIN 登入拿到 token，後台才會回應。
3. 部署後複製網址（`https://script.google.com/macros/s/…/exec`）。
4. 把網址貼到 `index.html` 最上面的 `const SCRIPT_URL="";` 引號裡，推上 GitHub。

## 3. 停用舊後台

> **待辦（2026-11-13 確認仍未停用）：** 舊網址 `…/AKfycbwvWw4l…/exec` 仍會回傳舊成員資料。舊 Sheet 沒有重要資料、舊 PIN 已不再使用，所以先跳過；但舊後台和新後台共用同一個 Google 帳號的執行額度，有空時請照下面步驟封存。

舊網址已經留在 git 紀錄裡，任何人都能直接呼叫，一定要停掉：

1. 打開**舊的** Apps Script 專案。
2. 「部署 → 管理部署作業」，把舊的部署全部「封存」。
3. 用瀏覽器打開舊網址確認：應該出現錯誤頁，而不是資料。

## 4. 全員設定新 PIN（上面都完成後才做）

1. 用管理者帳號登入新網站，點底部 👥「管理成員」。
2. 先按管理者那列的「重設 PIN」，換成你自己記得的 PIN。
3. 逐一新增成員，每人設一組 6 位數以上的 PIN，私下告訴本人。舊 PIN 不要再用。

## 5. 確認 Sheet 的共用設定

- 新 Sheet 右上「共用」：只有 Tori 的帳號，**不要**開「知道連結的人」。
- 舊 Sheet 也照樣檢查一次。

## 驗收方式

- 不帶 token 直接呼叫後台，所有動作都會回傳 `UNAUTHORIZED`（只有登入畫面要用的 `publicMembers` 和 `login` 例外，前者只回傳姓名、顏色、角色）。
- 瀏覽器開發者工具的「網路」分頁裡找不到任何人的 PIN。
- 一般成員呼叫成員管理、重設 PIN、刪除任務，都會回傳 `FORBIDDEN`。
- 同一帳號連續輸錯 5 次會鎖 15 分鐘。

本機可以跑自動測試（不需要 Google 帳號）：

```bash
node apps-script/test/backend.test.js
```

## 忘記管理者 PIN

打開 Apps Script 編輯器，執行 `resetAdminPinFromEditor`，到「執行記錄」看新的 PIN。只有能開這份 Sheet 的帳號才做得到。
